# 面板内截屏分析（V2）

最后更新：2026-09-19，版本 **0.8.1**。本文与实现保持一致。

助手面板里的「截屏分析」：点一下 → 框选聊天区域 → 端侧 OCR → 结果回到面板 → 在面板里就地分析。

## 触发与状态（与实现一致）

| 输入框状态 | 「分析」按钮 |
| --- | --- |
| 空 | **禁用**，文字为「先粘贴或截屏」，按钮下方直接写明原因 |
| 有内容（手输 / 剪贴板 / 截屏结果） | 启用，文字为「分析」 |

这样做的原因：按钮原先永远"看似可点"，输入为空时点击只在可滚动面板的**最底部**写一行错误，面板一长就看不见，用户看到的是"点了没反应"。

## 完整流程

```
面板「截屏分析（框选聊天区域）」
  → 面板视图被摘除（否则覆盖窗口会出现在截图里）
  → 区域选择（半透明，能看到下方聊天；按钮等分宽度，自适应各屏幕）
  → MediaProjection 授权
  → 截帧 + 裁剪到所选区域
  → 端侧 OCR（ML Kit 捆绑中文模型，离线）
  → 按行的水平位置推断说话人，拼成「说话人：内容」
  → 结果回填面板输入框，面板**重建视图**并恢复
  → 用户点「分析」
```

## 说话人推断（关键，否则分析退化为通用模板）

`PlainTextDialogueParser` 要求「**说话人：内容**」格式（标签 ≤20 字、不含数字与空格）。OCR 只给出文字，因此若直接按行拼接，每一行都会成为 `UNKNOWN` 说话人，分析器只能退回通用模板 —— 表现就是"截屏分析不出东西"。

`OcrTextAssembler.assembleWithSpeakers(lines, imageWidth)` 用**行的水平位置**推断：

| 行的位置 | 归属 |
| --- | --- |
| 明显偏右（越过中线 6% 以上） | `我：` |
| 明显偏左 | `对方：` |
| 跨越大半宽度（≥82%） | **不归属** |
| 紧贴中线 | **不归属** |

**宁可不说，不要错说。** `ScreenCaptureService` 调用该方法并传入位图宽度。

## 已修复的缺陷（按发现顺序）

| # | 症状 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | 面板按钮绕过 `hide()`，面板被截进图并被 OCR | 按钮直绑 `onStartCapture` 回调 | 改走 `beginCapture()` |
| 2 | 回传结果无人接收 | 逻辑写在 `onCreate`，但 `MainActivity` 是 `singleTask`，返回走 `onNewIntent` | 抽出 `handleAssistantIntents()`，两处都调 |
| 3 | 截屏后不重新显示 | 截屏前 `hide()` 销毁视图，返回时重建，中间跨授权弹窗丢失状态；且进程被回收 | 改为挂起而非销毁 |
| 4 | 截屏分析自动跳进 App | `onFinished()` 无条件 `startActivity(MainActivity)` | 直接回传面板；仅服务不存在时才回落 |
| 5 | 面板恢复后不显示 | 复用被 `removeView` 标记过的 `LayoutParams`，面板被加成悬浮球的尺寸 | 每次挂载新建 `LayoutParams`；用 `removeViewImmediate` |
| 6 | **截屏后面板所有按键失效** | 把 `removeViewImmediate` 摘下的**同一个 View** 再 `addView` 回去，窗口能显示但**输入链路未重建**，于是整个面板"看得见、按不动" | **重建视图**（`attach()`）+ 状态提升到 `AssistantPanelState` |
| 7 | 「分析」点了没反应 | 按钮恒可点，空输入时错误只写在可滚动面板最底部 | 按钮随输入状态启用/禁用，并直接显示原因 |
| 8 | 截屏文字分析不出东西 | `OcrTextAssembler.assemble()` 丢弃位置信息，全部成为 `UNKNOWN` 说话人 | 新增按位置推断说话人 |

**教训（#5 与 #6 同源）**：不要复用被 `removeView` 处理过的对象 —— 无论是 `LayoutParams` 还是 `View` 本身。前者导致几何错乱，后者导致输入链路失效，两者都表现为"窗口存在、`isVisible=true`、却不正确"。

## 验证

**模拟器（完整链路）**

```text
panel capture region: CaptureRegion(left=200, top=700, right=1080, bottom=1200)
frame 880x500 avgLuma=227 nonBlackSamples=448/448   ← 裁到所选区域且非黑屏
panel capture: active=true chars=61
assistant panel resumed (rebuilt)                    ← 视图重建
点「收起」后覆盖窗口数: 1                             ← 触摸已恢复
```

**真机（一台 Redmi 机型 / Android 16 / HyperOS）**

用户人工确认 0.8.1 全部通过：截屏后面板按键正常、分析可触发。

早期版本（0.7.0）真机三次截屏分析的记录（`chars=83/163/173`）保留了当时"面板恢复"的证据，但**当时的恢复方式已被 #6 替换**。

## 已知边界

- 依赖 `SYSTEM_ALERT_WINDOW`；重装 APK 后 HyperOS 会清除该权限，需重新授权（首页已提示）。
- 该设备在**开启**「屏幕共享保护」时截到空帧；关闭后才可用。
- 说话人推断基于左右分栏，遇到**居中气泡、群聊多人、或整行满宽**的消息不会归属 —— 这些行在面板里可见，需要用户自行补标签。
- 面板是只读展示 + 复制；不写入日历/待办，不自动发送。
- 仍是 Mock 引擎：「内置案例」有固定演示结果，其他文本走通用模板。
